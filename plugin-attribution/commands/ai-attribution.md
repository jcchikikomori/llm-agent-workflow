# ai-attribution

## Workflow: Anti-Slop First

Before composing ANY external post, follow this order:

1. **Compose** concrete, specific content — state what changed and why
1. **Self-check for AI slop** (see below) — remove any banned filler
1. **Structure review comments** as location -> problem -> proposed fix
1. **Append the attribution line** as the last line of the body
1. **Show the user** the complete post and get approval
1. **Post only after the user confirms**

## Banned AI-Slop Phrases (Blocked)

The hook blocks posts containing these phrases (case-insensitive). Never use
them in external posts:

- `this commit`, `in this PR`
- `comprehensive`, `robust`, `seamless`
- `great job`, `thanks for this`
- `I think maybe`, `you might consider`

Rewrite with plain, factual language. For example:

- ❌ "This is a comprehensive fix for the robust refactor."
- ✅ "The retry loop now backs off exponentially; added a regression test for the timeout path."

## Review-Comment Quality Pattern

Review comments MUST follow this structure:

> **location** -> **problem** -> **proposed fix**

Example:

> `app/services/billing.rb:42` -> the `unless` guard makes the early return
> unreachable -> invert the condition and return early.

## Core Rule

Every post to an external platform MUST end with:

> 🤖 Written by \<Family\>, reviewed by \<name\>

`<Family>` is the family of the model writing the post (`Claude`, `GPT`, `Gemini`, `DeepSeek`, `Mistral`, `Llama`,
`Qwen`, `Grok`, `Kimi`, `GLM`, or `AI` for anything else). The plugin accepts any family, and its block message shows
the exact line for the current session.

`<name>` comes from `${XDG_CONFIG_HOME:-~/.config}/llm-agent-workflow/attribution-name.txt`. The 1.x name files
under `~/.config/opencode/` and `~/.claude/` are still read, so an existing name keeps working; they are never
written.

## Setup

On first use, if no name file exists:

1. Ask the user: "What name should appear in the attribution line?"
1. Save their answer:

   ```bash
   mkdir -p "${XDG_CONFIG_HOME:-$HOME/.config}/llm-agent-workflow"
   echo "<name>" > "${XDG_CONFIG_HOME:-$HOME/.config}/llm-agent-workflow/attribution-name.txt"
   ```

1. Proceed with the original task

## What Counts as External Posts

ANY MCP tool call that includes a body/content/message field:

- GitHub: PR descriptions, issue comments, review comments
- JIRA: issue comments, issue descriptions
- Confluence: page content, comments
- Slack: messages
- Any other MCP-connected platform

Also CLI commands: `gh pr create`, `gh issue comment`, etc.

## How to Apply

1. Compose the post body (slop-free)
1. Append the attribution as the **last line** of the body:

   ```text
   🤖 Written by <Family>, reviewed by <name>
   ```

1. Do NOT add it to titles, labels, or metadata fields — only the body/content
1. For Bash CLI commands (`gh`, `curl`, etc.), always include the attribution **inline** in the body string — never
   use shell variable expansion like `${ATTR}` to inject it, because the plugin inspects raw command text before
   shell expansion

## Commit Messages

The plugin also blocks AI-generated trailers in `git commit` messages:
`Co-authored-by:` lines naming AI models, and `generated by/with <AI>` or
`assisted by <AI>` lines. Keep commit messages concise and factual.

## User Review Before Posting (Mandatory)

Before making ANY external post, you MUST:

1. Show the user the **complete post content** (including the attribution line)
1. Clearly state **where** it will be posted (platform, repo, issue number, channel, etc.)
1. Ask: "Ready to post this? (yes/no)"
1. **Only post after user confirms.** If user says no, ask what to change and revise.

This applies to ALL external posts — GitHub PRs, issue comments, JIRA comments,
Slack messages, Confluence pages, review comments, and any other platform.

Never skip this step. The attribution line says "reviewed by" — the user must
actually review it.

## When the Hook Blocks

If the plugin hook blocks your post:

1. Read the error message — it names the exact problem (missing attribution, slop phrase, or AI trailer)
1. Fix the content accordingly (add attribution, rewrite slop, remove AI trailer)
1. Show the updated content to the user for review
1. Retry the tool call only after user approves
