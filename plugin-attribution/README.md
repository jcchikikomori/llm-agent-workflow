# ai-attribution

Anti-AI-slop + attribution governance for external posts, on Claude Code and opencode. Ensures every post made
through any MCP-connected platform carries a visible AI-authorship attribution line, and keeps the post itself free
of AI-slop filler:

> 🤖 Written by \<Family\>, reviewed by \<name\>

`<Family>` is the model family that wrote the post: always `Claude` on Claude Code; on opencode the family of the
session's model (Claude, GPT, Gemini, DeepSeek, Mistral, Llama, Qwen, Grok, Kimi, GLM, or `AI` when unknown). The
check accepts any family; only the suggested line in the block message is model-aware.

## How It Works

- A **PreToolUse hook** matches all MCP tools (`mcp__.*`) and Bash commands dynamically — no hardcoded platform names.
- The hook scans `tool_input` for body-like fields (`body`, `content`, `message`, `comment`, `commentBody`,
  `description`, `text`).
- **Attribution**: posts missing the attribution line are **blocked before they are sent**. The check is
  family-agnostic: one line `Written by <X>, reviewed by <name>`, where `<X>` is 1-40 characters with no comma.
- **Anti-slop**: posts or posting commands containing clear AI-slop filler phrases (`this commit`, `in this PR`,
  `comprehensive`, `robust`, `seamless`, `great job`, `thanks for this`, `I think maybe`, `you might consider`) are
  **blocked** with guidance to rewrite concretely. Review comments should follow the quality pattern:
  **location -> problem -> proposed fix**.
- **Commit quality**: `git commit -m` / `-F` invocations with AI-generated trailers (`Co-authored-by:` naming AI
  models, `generated by/with <AI>`, `assisted by <AI>`) are **blocked**.
- **Fail closed**: a reviewer-name file that cannot be read (permissions, a directory, bad encoding) counts as "not
  configured" and blocks with the setup message.
- A companion **skill** instructs the model to compose slop-free, attribution-carrying posts and to **show the post to
  the user for review before sending**.

### On opencode

`plugins/opencode-ai-attribution.ts` (export `AiAttributionPlugin`) runs the same checks in `tool.execute.before`,
for every model. The family comes from `chat.params` (`model.id` first, then `model.providerID`). MCP tools are
recognised by the server names in the opencode config (`<server>_<tool>`, sanitized the way opencode does) and by the
`mcp__` prefix; the `slack` server is exempt. Install it with `setup-opencode.sh --plugin ai-attribution`.

## Supported Platforms

Works with **any** MCP-connected platform, including:

- GitHub (PRs, issues, review comments)
- JIRA (issue comments, descriptions)
- Confluence (pages, comments)
- Any future MCP server with body-like fields

Also covers CLI tools: `gh pr create`, `gh pr comment`, `gh issue comment`, `gh api`, `curl POST/PUT/PATCH`, etc.

### Native Attribution Exceptions

Some platforms provide their own built-in AI attribution, making the manual text line unnecessary. These are
**exempt** from the text check:

| Platform | Native label | Hook behaviour |
| --- | --- | --- |
| Slack (`mcp__slack__*` on Claude Code; server `slack` on opencode) | "Sent using @Claude" added by Slack automatically | ✅ Skipped — native label is sufficient |

To add more exempt platforms, extend `NATIVE_ATTRIBUTION_TOOL_PATTERNS` in `hooks/attribution_hook.py` and
`NATIVE_ATTRIBUTION_SERVERS` in `plugins/opencode-ai-attribution.ts`.

## Setup

### 1. Install the plugin

```console
/plugin install ai-attribution@llm-agent-workflow
/reload-plugins
```

### 2. Set your name (first use)

The plugin prompts for your name on first use. To set it yourself:

```bash
mkdir -p "${XDG_CONFIG_HOME:-$HOME/.config}/llm-agent-workflow"
echo "Your Name" > "${XDG_CONFIG_HOME:-$HOME/.config}/llm-agent-workflow/attribution-name.txt"
```

One file serves both runtimes.

## Migrating from claude-attribution

2.0.0 renames the plugin, so Claude Code needs a reinstall under the new name:

```console
/plugin uninstall claude-attribution@llm-agent-workflow
/plugin install ai-attribution@llm-agent-workflow
/reload-plugins
```

The reviewer name now lives at `${XDG_CONFIG_HOME:-~/.config}/llm-agent-workflow/attribution-name.txt`. The old
files, `~/.claude/claude-attribution-name.txt` and `~/.config/opencode/claude-attribution-name.txt`, are still read
(the new file wins when they disagree), so you are not asked for your name again. Nothing writes to them any more.

On opencode, re-run `setup-opencode.sh`: it installs `plugins/opencode-ai-attribution.ts` and
`commands/ai-attribution.md`, removes a tracker-recorded `plugins/opencode-claude-attribution.ts` with
`[REMOVED-LEGACY]`, and reports an untracked `commands/claude-attribution.md` with `[LEGACY-UNTRACKED]` without
touching it. `--plugin attribution` still works, with a `WARN: use ai-attribution`.

## User Review Flow

Before posting to any external platform, the model will:

1. Compose a slop-free post with concrete, specific language
1. Add the attribution line
1. Show the **complete post content** to the user
1. Ask for approval before sending
1. Only post after user confirms

- **Breaking**: renamed `claude-attribution` to `ai-attribution` — plugin id, skill (`skills/ai-attribution`), slash
  command (`/ai-attribution`), marketplace entry; `package.json` is `opencode-ai-attribution`. Reinstall on Claude
  Code; see "Migrating from claude-attribution".
- The attribution line names the model family: `🤖 Written by <Family>, reviewed by <name>`. The validator accepts
  any single-line family (1-40 characters, no comma), so existing `Written by Claude` lines keep passing.
- Reviewer name moved to `${XDG_CONFIG_HOME:-~/.config}/llm-agent-workflow/attribution-name.txt`; the 1.x files
  `~/.claude/claude-attribution-name.txt` and `~/.config/opencode/claude-attribution-name.txt` are read as fallbacks
  and never written.
- An unreadable or undecodable name file now blocks with the setup message instead of letting the post through.
- opencode port renamed to `plugins/opencode-ai-attribution.ts` (`AiAttributionPlugin`): every check runs for every
  model (the Claude-only skip is gone), the family comes from `chat.params`, MCP tools are detected from the
  configured server names (`<server>_<tool>`) as well as the `mcp__` prefix, and `git commit -m`/`-F` matching no
  longer throws under `matchAll`.
- Block messages use the `[ai-attribution]` prefix; the skill description is 245 bytes.
- `setup-opencode.sh` removes the tracker-recorded 1.x files (`plugins/opencode-claude-attribution.ts`,
  `commands/claude-attribution.md`) and accepts `--plugin attribution` as an alias with a WARN.
- Tests: `tests/test_attribution_hook.py` extended (family, name files, fail-closed reads) and a new bun suite
  `tests/opencode-ai-attribution.test.ts` (family table, MCP detection, name files).
